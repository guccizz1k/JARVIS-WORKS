# V6.4 외부 증빙 자동 인식 / 독립 검토 기록

- 기존 `/api/imports`는 정형 견적/발주만 담당. 새 `/api/evidence`는 영수증·매출/매입전표·거래명세표·재고 현황표 전용이며 공식 회계전표/입금/재고 원장을 수정하지 않는다.
- 사진 PNG/JPEG/WEBP, 검색/스캔 PDF(최대 4쪽), 단일 시트 XLSX(5MB). OCR은 시스템 Tesseract `kor+eng`와 Pillow/PyMuPDF가 필요하다.
- 인식과 분류는 **후보**이다. 모호한 문서는 인식된 필드/메시지를 보여주고 사용자가 원본을 확인해 적법한 분류·값을 보완하도록 한다.
- 원본 파일 바이트는 DB에 저장하지 않는다. 파일 SHA256, 분류 결과, 최대 1,600자 추출 텍스트, 검토 변경 필드가 저장된다. JW_DATA_KEY 설정 시 스냅샷 암호화를 사용한다.
- 원본 승인에는 `preview_digest`, `original_checked: true`, 명시적 목적(sales/purchase/expense/inventory_snapshot), 거래처·날짜·금액(재고 제외), 재고 품목코드·수량(재고 한 품목)이 필요하다.
- 업로더/관리자만 24시간 이내 승인 가능; 기관별 스코프, 파일 해시 및 원본 문서번호 중복 확인, CSRF, 로컬 파일 스캔 기존 규칙을 재사용.
- 독립 대시보드/원래 대시보드 집계에는 **별도 검토 완료 증빙**만 포함. 매출 집계는 기존 확정 청구서/입금액과 혼합하지 않음.
- 중요 한계: OCR 자유형식의 문자 정확도 보증 불가, 다중 품목 재고 일괄 자동 등록 미지원, 인식 항목은 공급가액/세액/총액 불일치의 자동 정정 불가, 법정 세금계산서 발행 미지원, 실재고 수불 미지원. PG17 RLS, iPhone Safari, 운영 전용 샌드박스/네트워크 격리, 개인정보 정책/외부 보안심사는 NOT RUN.
- 운영 환경에서는 `JW_UPLOAD_SCAN=clamav` 및 ClamAV가 없으면 업로드 차단(기존 규칙). OCR 언어 패키지가 없으면 승인 가능한 증빙을 추측하지 말고 실패시킨다.
