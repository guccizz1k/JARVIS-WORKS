# JARVIS WORKS V7.1~V7.5 — 구현·검증 경계 (검토용)

본 기록은 로컬 코드·합성 테스트 범위만을 설명합니다. 실제 PostgreSQL 전환, 공식 세무 회계 처리, 운영 배포 완료를 의미하지 않습니다.

## V7.1 / 데이터 이행 및 기업 간 격리

- 관리자만 조회 가능한 `GET /api/operations/integrity` 구현: 기업별 거래처·견적·발주·청구·입금 링크, 품목 출처, 감사 행위자, 승인 조정 생성자를 대조하고 집계 **건수만** 반환. 원본·타 기업 식별정보 노출 없음.
- 입금액이 승인 조정 후 청구액을 초과하거나 원본 청구 계산에 실패한 경우 `review_required`.
- 검사 대상 청구서가 상한을 초과하면 **불완전 검사이며 절대 PASS가 아님**. 하나의 SQLite 읽기 스냅샷으로 동일 시점 검사.
- PostgreSQL 전환 사전점검: 현재 SQLite 테이블 목록과 과거 PostgreSQL 격리 시험용 DDL을 비교, 미이행 테이블을 집계하고 실제 운영 컷오버를 항상 차단.
- **미완료:** PG 17 실제 시험 서버 및 운영 전체 스키마로 RLS/마이그레이션/rollback 시험, 실제 앱 저장소를 PostgreSQL로 교체, 데이터 정합성 재검증.

## V7.2 / 복구와 성능

- 별도 합성 DB에서 트랜잭션 강제 예외 롤백, 암호화 백업, 비트 변조 거부, 올바른 복원, 원본 보호, 잘못된 복호 키 거부를 수행.
- 동시 읽기 로컬 부하를 측정해 p50/p95/max를 기록. 측정치에는 반드시 `demo synthetic only`, `production_sla_measured:false` 첨부.
- **미완료:** 실제 PostgreSQL 장애 절체·PITR, 실제 운영 데이터 규모의 성능, 실측 RPO/RTO 및 목표치 합의, 공격 시뮬레이션과 외부 보안 검증.

## V7.3 / 호환성 및 시나리오

- 기존 PC/모바일 Chromium 문서 업로드·승인 및 복합 정산 흐름 재시험.
- 로컬 실제 HTTP에서 쿠키 인증, 기업별 운영점검, 비인증 차단, 외부 Origin 쓰기 차단 검증.
- **미완료:** 실기기 iPhone Safari, 실제 거래처 입력 문서, 고객사 업무환경, 접근성·호환성 외부 검수.

## V7.4 / UI

- 사용자 합의에 따라 **핵심 기능 및 운영 기술 검증 완료 후 일괄 정비**. 이번 변경에서 디자인, 사이드바, 메신저 UI는 바꾸지 않음.
- 출시용 최종 디자인 품질검증은 아직 시작하지 않음.

## V7.5 / 출시

- `python -m scripts.release_gate_v75`는 출시 차단 조건을 JSON으로 출력하고 exit code **2 (BLOCKED)** 로 종료. 이를 실패로 숨기거나 PASS로 바꾸지 않음.
- GitHub push / PR / 병합 / 외부 운영 배포 / 고객 DB 변경 **없음**.
- 최종 출시 승인 전 모든 독립 검증·시범운영·배포/복구 계획 서명이 필요.

## 파일 적용 방식

- 검증 기준: V7.0 로컬 검토 패키지의 고정 해시 원본.
- `addon/install_v75.py --check --root <isolated-dev-copy>`로 사전 검사하고, 격리 사본에 한하여 `--apply`를 사용.
- 패치의 기존 파일 버전/변조/심볼릭 링크/운영 환경 차단, 신규 파일 충돌 차단, 수행 중 예외 복원을 시험.
- 패키지에 포함된 V7.0 안전 설치도 운영환경을 거부함. 운영 적용 도구가 아님.
