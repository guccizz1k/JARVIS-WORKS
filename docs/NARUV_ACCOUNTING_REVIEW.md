# NARUV internal journal review

Baseline c3f89f48ba848ab3e0fd2754df5870718a3850a0: 21/21 CI jobs; 330/330 repeated native-to-finance cases. This extension adds 10 tests to the existing five-service disposable PG17 matrix; no production migration.

Finance events automatically create immutable journal headers and debit/credit lines in the same transaction. Deferred constraints validate both sides against source amount, zero-value events retain a header without money lines. AR/AP reconciliation uses the original finance event stream. Sales post AR / sales / output VAT; purchase posts AP / purchase clearing / input VAT. Payment uses cash clearing, reversal swaps original lines. These are lab account mappings only, not a statutory chart of accounts, recognized revenue policy, inventory valuation or actual bank movement. Posting date is the DB event timestamp in Seoul month; only the seeded current month is available. Closed period rejects new postings without reopening; exact existing request retry remains readable. Closing uses the same tenant lock as finance. Test harness resets synthetic fixture only. No production close, paid service, real cash, tax invoice, external AI or main/deploy change; actual CI usage cost unmeasured.

Tests cover purchase/payment/reversal, sale, zero, period close/duplicate retry, tenant, close/payment race, journal failure, deferred imbalance, permissions and partial billing. Multi-line trade, inventory cost and COGS, statutory accounting, prior-period adjustments, period opening/admin approval and migration of existing events, real bank/tax integration, UI, recovery and independent QA remain release blockers. All success claims depend on actual CI.
