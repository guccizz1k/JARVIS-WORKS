# JARVIS WORKS V6.6–V6.8 — 다중 품목 대조·불일치 검토 이력·Excel 품목 후보

## 구현 범위

- V6.6: 담당자가 원본과 대조한 판매 증빙의 최대 40개 품목(품명, 선택 품목코드, 수량, 단가)을 별도 테이블에 1회 확정. 수정/삭제·타 기업 접근·사후 연결 변경 차단. 멱등 재시도.
- V6.6: 내부 견적·발주·청구 품목과 이름을 일치시켜 부분 수량, 초과 수량, 단가 불일치, 미대조 품목, 중복 품목명을 표시. **상품코드는 내부 원본에 코드 필드가 없어 자동 확인하지 않음.** 서로 다른 상품을 추정 매칭하지 않음. 일부 납품은 계약과의 차이로 기록하되 실제 납품 인정은 하지 않음.
- V6.7: 거래 증빙의 미연결·연결 불일치·연결 후 원본 변경·미지원 방향에 대한 사람의 조사/확인 이벤트를 append-only 해시 체인으로 보존. 확인은 회계처리 또는 오류 해결을 의미하지 않음. 체인은 내부 변조 감지 보조 장치이며 외부 공증을 제공하지 않음.
- V6.8: 명확한 품목명/수량/단가 열이 있는 단일 XLSX의 품목별 **후보** 제시. 명시적 금액 열이 수량×단가와 다르거나 자료가 애매한 경우 후보를 만들지 않음. 최대 40건; 원본 업로드를 보존하지 않으며 담당자의 최종 승인이 필요함.
- 기존 화면에 최소 입력 동선만 연결. UI 전체 리디자인은 보류.

## 배제 범위 및 차단

- 실제 회계 전표 자동 확정, 세금계산서 발행, 결제/송금, 매입 전표의 매출 측 링크, 실재고 증감, 외부 상품코드 마스터 매칭을 수행하지 않음.
- 할인·운임·반품·부분 환불의 금액 재배분, 외부 PDF/사진에서 테이블 완전 추출은 **미구현**. 과세와 면세 혼재, 복합 세율, 외화 거래는 비교 정확도를 보증하지 않음.
- 운영 DB는 여전히 SQLite 참조 구현이며 production 시작을 차단함. 외부 PostgreSQL/RLS, 실제 Safari/고객사 문서 인식 정확도는 미검증.
- 실제 고객 데이터 없이 합성 시험만 실시. 원본 파일은 서버에 영속 저장되지 않으므로 감사·법정 증빙을 보증하지 않음.

## 남은 출시 게이트

1. 사업자/상품 기준정보 및 매출/매입 연동 정책, 반품·할인·운임/부가세 규칙의 도메인 확정.
2. 실제 서식별 PDF/사진 OCR 정밀도 골든셋을 권한 있는 사업자 문서로 확보·검증.
3. PostgreSQL 운영 스키마 이식, 모든 신규 테이블 RLS 정책·교차 테넌트 공격 테스트·동시성 스트레스 검증.
4. 별도 OCR/파일 검사 서비스 큐·악성 문서 검사·레이트리밋·복구 리허설.
5. 실 iPhone Safari와 PC 브라우저, 고객사 Pilot 및 운영 감사.
6. 핵심 기능 완료 후 통합 UI 개선, 접근성·서비스 온보딩과 배포 승인.

상태: 로컬 검토 후보. 프로덕션 사용 불가.
