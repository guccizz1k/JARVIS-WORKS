# S4 과거 원장 연결 · 독립 검증 규약 (감사 전용)

## 목적과 완료 조건

- 기존 거래 원장 `jw_dev.quotes`(v92)와 신규 `jw_dev.cinema_pg_quotes`(CINEMA) 간의 **동일 거래라는 주장**을 검증한다.
- `Q-...`와 `T...` 거래번호는 서로 다른 식별 체계이며, 날짜·회사명·금액·사업자번호의 일치만으로 거래 동일성을 확정하지 않는다.
- 기존 데이터를 삭제·재기입·자동 이관하지 않는다. 기존 납품·청구·입금의 금액을 임의 합산하지 않는다.
- 실행 순서: 원본 스냅샷 독립 획득 → 같은 org 아래의 **명시적인 1:1 매핑 제출** → 품목/수량/단가/VAT/사업자번호/승인 상태 비교 → 두 원본의 SHA-256 재계산 → 담당자 신원·결재·불변 감사증빙을 실제 서버에서 검증 → 승인된 연결만 읽기 전용 집계 적용.
- **현재는 앞 절반의 정적·합성 검증만 구현했다.** 마지막 실서버 검증·매핑 저장·회계 반영은 구현/검증되지 않았으므로 BLOCKED이다.

## 추가 파일

- `app/pg_cinema_s4_reconciliation_v1.py`: 외부 DB에 접속하거나 데이터를 변경하지 않는 순수 Python 감사 함수. 반환되는 `publishable` 값은 설계상 항상 False. 사용자 입력으로 만든 해시·검토자 문자열은 승인 증명이 아니므로 **회계 보고서 승인에 사용 금지**.
- `tests/test_cinema_pg_s4_reconciliation.py`: 두 원장 식별자·테넌트·사업자번호·VAT·품목별 수량·단가·취소·중복·한쪽 누락·위조/오래된 해시·임시 합계 차단 반례. 원본 없음·미승인 매핑에서 PASS 집계를 만들 수 없음.
- 기존 `scripts/review/cinema_pg_s4_atomic_gate.sql` 및 `scripts/ci_cinema_pg_s4_atomic_gate.py`: 일회용 PG17에서만 DB-level 서로 다른 원장 쓰기 동시 충돌을 시험. 실제 공유 DB에 적용 금지.

## 정책

1. `ReviewedLink`는 자동 식별자가 아니라 *관리자 검토 후보*이다. 같은 사업자번호+금액이라도 계약일/문서가 다를 수 있으므로 자동 연결하지 않는다.
2. `legacy_quote_id` 및 `cinema_quote_id`는 각각 같은 org에 실제 존재해야 한다. 다른 조직의 동일 ID는 거부.
3. 품목은 정렬된 다중집합으로 정확히 비교한다. 이름·수량·단가가 하나라도 달라지면 차단. VAT 방식/취소 상태도 일치해야 한다.
4. 두 스냅샷은 독립 서버 데이터 원천에서 읽어야 하며, 원본 해시 검증과 실제 사용자 결재 증거를 서버에서 획득하기 전에는 회계 집계·원장 전환을 허용하지 않는다.
5. 누락된/애매한 연결이 하나라도 있으면 안전한 단일 합계라고 보고하지 않는다. `provisional_unique_subtotal`은 합성 감사 참고용 수치이지 회계/대시보드 출력이 아니다.
6. 실제 개발 DB에는 아직 신규 엔진 테이블과 역할이 없고, 원장 4종은 모두 0건이었다(2026-11-05 읽기 전용 확인). 따라서 **실거래 기준 정확도·연결 성공률은 NOT MEASURED**.
7. 기존 개발 DB 영구 마이그레이션은 보안 검토 차단 상태. 다른 경로로 우회하지 않는다.
8. CINEMA 원본 HTML, `app/main.py`, `app/static/`, 운영 DB, 고객 자료, GitHub `main`은 변경 금지.
