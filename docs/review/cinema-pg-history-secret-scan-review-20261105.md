# JARVIS-WORKS — 전체 Git 이력 비밀정보 검증 (2026-11-05)

## 범위와 결과 구분
- GitHub 저장소가 **PUBLIC**임을 직접 확인했다.
- 기존 200커밋/정규식 점검 대신, 기존 `jw-cinema-pg-gates.yml`의 격리 CI에서 Gitleaks **v8.30.0 전체 `--all` 이력** 검사로 확장했다.
- 검사 바이너리의 압축파일 SHA-256을 고정하고 다운로드 직후 실제 검증한다. 비밀값은 redacted JSON으로만 임시 저장하며 CI 아티팩트나 stdout에 남기지 않는다.
- 초기 4건 + 후속 검증기 소스에서 발견된 1건, 합계 **5건**은 전부 `generic-api-key` 규칙이다. GitHub의 특정 커밋과 Git blob SHA 및 소스 행을 독립 대조했다. 실제 인증 키나 계정 비밀번호의 유출이 아니라, 아래 합성/검증 자료를 휴리스틱이 탐지한 결과이다.
- 예외 항목은 `scripts/ci_cinema_pg_history_classifier.py`의 정확히 지정된 **다섯 가지 (규칙, 커밋 SHA, 경로, 행 번호, Git blob SHA)** 만 인정한다. 프로그램은 실제 `git show`로 해당 행의 *합성 문맥*까지 확인한다.
- 다른 위치, 다른 커밋, 다른 blob, 다른 규칙, 중복 항목 또는 새로운 탐지는 **BLOCKED**로 처리한다. Gitleaks 검사 자체를 중단하거나 일반 규칙을 끄지 않는다.

## 독립 확인된 네 오탐의 종류

1. 기존 `scripts/ci_cinema_pg_guard.py`: 보안·무결성 용도로 고정한 **Git blob SHA 상수**. 비밀키가 아니다.
2. 구형 `tests/test_messenger_v22.py`의 한 역사적 커밋: 합성 `example.test` 로그인 계정의 시험 비밀번호.
3. 동일 테스트 파일의 다른 역사적 커밋: 동일하게 고정된 합성 시험 계정.
4. 구형 `tests/test_pg_auth_v85.py`: **비밀번호 검증 함수 자체의 monkeypatch** 및 가짜 해시 확인 코드. 실제 비밀번호/키를 포함하지 않는다.
5. 초기 보안 분류기 `scripts/ci_cinema_pg_history_classifier.py`의 역사적 커밋: 과거 PBKDF2 비밀번호 검증 **함수명 자체를 비교하는 Python 소스 문자열**. 외부 서비스 키 또는 실제 인증정보가 아니다. 커밋·행·Git blob을 고정해 분류한다.

## 기밀 보호
- 탐지된 내용/문자열/설정 파일을 공개 워크플로 로그에 출력하지 않는다.
- 로그에는 전체 이력 스캔 결과 개수, 검증된 오탐 수, 신규·미확인 항목 수만 남긴다.
- 과거 Git 커밋을 재작성하지 않았으며, 기존 테스트 코드를 삭제하거나 비밀값으로 덮어쓰지 않았다.
- 합성 비밀번호가 실제 서비스에도 사용됐다는 증거는 **없음**. 실제 API 보안 검증은 별개이다.

## 남은 출시 차단
- **PUBLIC → PRIVATE** 전환은 별도 승인 및 접근 권한 확인 전까지 실행하지 않는다.
- Gitleaks는 서명 키 유출과 패턴 기반 비밀값 탐지에 대한 검사일 뿐, 전체 소스·산출물의 개인정보 검수까지 자동 보장하지 않는다.
- Supabase 개발 DB 마이그레이션은 이전 안전 검토에서 거부됐으며, 다른 경로로 우회하지 않는다.
- 전체 GitHub Actions 성공과 실제 운영 데이터·Render HTTPS E2E의 성공은 서로 다른 증거이다.
