# NARUV native authorization fence and bounded staging — isolated review

Baseline aaf3aefc47e81d73477f33cb841ed56dfa52f803: 21/21 CI jobs, native write 90/90. This wave preserves those results at the baseline and adds ten independent cases to the existing five-service matrix (28 tests per fresh service). Do not claim the new candidate passes until CI confirms it.

Authorization: ordinary user/session/disabled-user DML is serialized with native import writes using transaction-scoped actor advisory locks. A separate NOLOGIN/NOBYPASSRLS owner stores a per-actor authorization generation; committed identity-changing mutations increment it, and staged reviews bind it alongside the existing session and three digests. Restoring a previous role, disabled flag or session expiry does not restore old authorization. Issuing an additional session alone does not invalidate existing sessions. Guard rechecks native identity after acquiring the same lock, requires READ COMMITTED, and checks again before durable receipt. Transaction rollback also rolls back generation changes. Ordinary TRUNCATE on auth tables is denied in the fixture. Actual DB lock waits are asserted with pg_blocking_pids, not inferred from sleeps. Lock ordering is actor then tenant quota then source then approval. Auth writers may already hold row locks; deadlock/timeout means rollback, not authorization. Privileged DDL/trigger disabling, database login-role membership changes, and real production auth-writer migration remain outside this proof.

Capacity: conservative lab-only limits of 128 retained stages and 16 MiB of logical UTF-8 canonical rows plus expected-ID JSON per tenant, across sources; no physical disk or system throughput claim. Exact retry bypasses the quota only for an unchanged, unexpired existing stage. No stage is automatically deleted or reused; quota exhaustion fails closed. Count/byte tests deliberately seed catalog-valid synthetic rows, not actual parser payload acceptance. Production retention, encryption, quotas, cleanup and capacity require a separate policy and real-environment evidence. Clock checks reject timestamps in the future; full monotonic-clock/restart guarantees remain unproved.
