# JARVIS WORKS V6.5 — 거래·증빙 보수적 대조

## 기능

- V6.4에서 승인한 내부 **매출** 증빙(매출전표/거래명세표)과 내부 견적/발주/청구 문서를 회사별로 비교한다.
- 거래처명(공백·기본 구두점 제외 정확 일치) 또는 문서번호가 일치하는 후보만 노출한다. **금액만 일치하면 후보로 보지 않는다.** 임의의 매칭 확률이나 정확도 점수는 산출하지 않는다.
- 총액은 기존 백엔드의 KRW VAT 계산 규칙을 재사용하고, 품목코드와 내부 품목명을 **정확히** 대조할 수 있을 때만 수량을 비교한다. SKU와 품목명이 다른 제품은 검증불능 경고로 표기한다.
- 금액/회사명/문서번호/품목/수량의 차이를 차이 목록으로 반환한다. 불일치가 있는 연결에는 담당자가 사유 12자 이상을 명시해야 한다.
- 사용자 원본 확인 동의, 서버가 재계산한 비교 해시, 회사별 접근 제한, DB 스키마 트리거, 감사기록으로 임의 연결과 이력 위조를 제한한다.
- 한 증빙 기록은 한 내부 문서와 연결 가능하며 연결 기록은 수정/삭제할 수 없다. 연결 시점 스냅샷과 현재 내부 거래를 비교해 변경 여부를 안내한다.
- 경비·매입·재고 실사는 내부 **매출** 문서에 강제로 연결하지 않는다. '지원하지 않는 방향'으로 표시한다.

## API

- `GET /api/evidence/reconciliation/queue`: 회사별 증빙 대조 대기/완료 현황 (최대 100)
- `GET /api/evidence/records/{record_id}/candidates`: 기본 정보가 일치하는 내부 거래 후보 (원본별 최대 120, 반환 최대 30)
- `POST /api/evidence/records/{record_id}/reconcile-link`: 명시적인 담당자 확인 및 내부 거래 연결, 해시 재검사
- `GET /api/evidence/records/{record_id}/reconciliation`: 고정 스냅샷 및 내부 거래의 후속 변경 검출

## 안전·제약

- 거래 확인, 거래 당사자 승인, 세금계산서 발행, 회계 전기, 결제, 재고 확정 등 **실제 업무 상태는 절대 변경하지 않는다**.
- 내부 원본 문서번호와 외부 거래 참조번호는 일치하지 않는 경우도 있으므로 자동 확정하지 않으며 불일치 검토 필수.
- OCR 정확도를 보증하지 않는다. 실제 고객사 문서 기반 평가 Precision/Recall은 NOT MEASURED.
- 문서의 단일 금액/단일 SKU 수준 대조. 다중 품목·할인·운임·부분 납품·대체품·환불/반품·매입처 방향 대조는 후속 개발.
- SQLite 격리 테스트만 완료. PostgreSQL/RLS/실제 Safari/운영 배포/부하 및 보안 독립감사는 별도 검증이 필요하다.
- 전면 UI 재설계 없음. 기존 문서 검토함에 최소한의 대조 확인 기능만 추가한다.
