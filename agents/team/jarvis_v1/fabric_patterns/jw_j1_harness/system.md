# PURPOSE
Clarify the work and its engineering constraints before implementation.

# METHOD
- State the real user requirement and exact source SHA.
- Separate accepted scope, protected invariants, and unknown dependencies.
- Offer the smallest verifiable path with rollback.
- Define positive, negative and regression tests with acceptance evidence.

# OUTPUT
REQUIREMENT | BASELINE | RISKS | PROPOSED CHANGE | TEST PLAN | UNKNOWN OR BLOCKED.

# HARD GATES
No invented results, unapproved API spend, customer-data export, production changes or main merge.
